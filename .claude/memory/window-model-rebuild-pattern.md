Rebuild the three window-gate quad models (quad-w1a, quad-w1b, quad-w1-combined) onto the shared `lib/quad` block pattern used by quad-noise/quad-l4. **DONE 2026-06-02**: quad-w1a (blueprint, 2026-06-01), quad-w1b, and quad-w1-combined all migrated; none keep a local `blocks/` dir anymore. All configs are now factories `quadW1xConfig(overrides?)`.

**Agreed design (from user):**
- `StepDef` is generalized in [[quad-block-library-consts]]'s consts.ts: `pos` is the universal anchor every step type carries (window center / waypoint target). Window steps carry `normal`/`width`/`height` on the bus and need **no** `threshold` (that's waypoint-specific). Labels are NOT on the bus — vis generates `W{idx}` itself.
- Shared `mission` is reused unchanged in behavior: `stepToBus` passes the type-specific fields through; mission only ever reads `pos` and delegates completion to the planner. `lifecycle.ts` `fmtStep` was generalized to render window fields into the editable source.
- The carrot-and-stick blocks live in **shared lib** alongside planner_wp/navigator_wp. `navigator_w1` (renamed from `navigator_w1a` on 2026-06-02) is the family-level navigator shared by the whole w1 family (w1a + w1b reuse it) — execution is identical, only planning differs. Planners are per-variant: `planner_w1a` (w1a) and `planner_w1b` (w1b, chosen as a dedicated block rather than generalizing w1a). Both do plane-crossing-within-frame detection and use a **pure-pursuit centerline carrot** (`gateCarrot` = `center + (sideScore+LOOKAHEAD)·normal`) so the forward pull never collapses at the frame; `planner_w1b` adds a pre-stage leg first (see below). navigator reads gains from `state.K`; w1a/w1b model-override KI_POS:0.3, MAX_TILT:0.4, KP_YAW_OUTER:5, YAW_MEAS_LPF:0.35 (yaw loop softened + measurement-LPF'd to kill vibration), MAX_RESTARTS:4, ACC_ERR_LIMIT:8000, MAX_TICKS:5000/simDuration:9000. planner tunables (LOOKAHEAD:4, MAX_YAW_RATE, YAW_SLEW_LPF:0.2) are also in `state.K`.
- **w1b pre-stage**: each gate's `StepDef.preStageDist` (threaded through shared StepDef/StepBus/stepToBus + lifecycle `fmtStep`) puts a pre-stage waypoint that far behind the gate along `-normal`. `planner_w1b` flies there first (point-seeking carrot, `preGateDone` latch within PREGATE_THRESHOLD=1.5) then switches to the centerline carrot. `preStageDist<=0` degrades it to exactly planner_w1a.
- **Block naming convention** (user's scheme): `w`=window, the digit = window-nav algo family (`w1` = carrot / pre-staging; `w2`/`w3`/… = future different algos), trailing letter = variant within the family (`w1a` = carrot, `w1b` = pre-staging). Keep names short. The carrot-follower navigator is shared across the w1 family as family-level `navigator_w1` (done 2026-06-02): same `_w1` (no trailing letter) signals it's family-wide, not variant-specific.
- **Miss handling** (changed 2026-06-02): planner reports shared mission's `STATUS_RESTART`; mission then owns the fly-back as a real **`PHASE_RESTART`** (phase 7) — it points the target at the step's start anchor (`segStart` = previous gate / HOME), and a second `planner_wp` block reports arrival via `statusReturn` so mission re-runs the same gate. The planner's old `recovering` flag was removed. `lifecycle.after` counts entries into PHASE_RESTART as `restarts` and `simTest` gates on `restarts <= K.MAX_RESTARTS` (a `-1` sentinel = "criterion N/A", skipped; waypoint models leave it -1). No PHASE_MISSED.
- Window route lives in model-local `route.ts` (StepDef[]), imported by BOTH config (→ `makeLifecycleBlock`) and vis (→ `windowGate` WindowDef[], mapping pos→center + `W{i}` label). Avoids a config↔vis circular import.
- Validator = shared lifecycle.after() (cross-track IAE + laps), shown via quad-noise-style infoOverlay.

- **quad-w1-combined** (dual-vehicle A-vs-B race, migrated 2026-06-02): two full lib stacks run in parallel under `state.vehicles.a` / `.b` (carrot vs pre-stage), wired via `va`/`vb`/`writeVehicle` helpers + a per-vehicle `vehicleBlocks()` factory; planner state slice is named `planner` uniformly for both (B's just has the extra `preGateDone`). Each vehicle flies its own OFFSET track, so: (1) the **lib mission was generalized to read home from K** — `HOME_X`/`HOME_Z` added to QuadConsts (default 0 = origin, so w1a/w1b/noise/l4 unchanged); HOME/LAND_PAD use them. (2) Each vehicle's mission `mapStateIn` injects a per-vehicle **K view** `{...K, steps: K.stepsA|stepsB, HOME_X, HOME_Z}` (planner/navigator/env just read shared `s.K`). (3) A **combined-local `lifecycle.ts`** (`makeCombinedLifecycleBlock`, NOT the lib's `makeLifecycleBlock`) publishes K (scalars + both routes merged in via mapStateOut so route.ts stays DRY) and its `after()` runs the lib per-vehicle cross-track/restart validator for both vehicles with a per-vehicle pass verdict. It uses closures (not rendered editable source — acceptable since the old combined had no editable K either). Routes + HOME_A/HOME_B in `quad-w1-combined/route.ts`.
