The sim engine ([src/sim/engine/engine.ts](src/sim/engine/engine.ts)) splits state into **dynamic** (evolves per tick, stored in `history`) and **static** (built once, not duplicated into history).

Mechanism (built 2026-05-31):
- `BlockConfig` gained `static?: boolean` and `staticKeys?: string[]`. A static block runs ONCE in config order via `computeStaticState` — at `initSim`, and re-run on `startSim` (when staged code applies) and `revertBlock` of a static block. Its `mapStateOut` output populates `inst.staticState`.
- `doTick` skips static blocks; for dynamic blocks it merges the static slice into the block's view: `block.mapStateIn({ ...state, ...inst.staticState })` (static spread LAST so it's authoritative). `mapStateOut` only receives dynamic `state`, so static never enters `inst.state`/`history`.
- New accessor `getStatic(simId)` returns the slice (e.g. `{ K }`). O(1), stable for the run.

Contract — **the honest/explicit approach** (JS has no operator overloading, so raw `history[i].K` cannot be transparently injected; we don't try): `state` and every `history[i]` are dynamic-only; static is reached ONLY via `getStatic()` and an explicit argument. Charts/vis APIs changed:
- `ChartSeries.fn` is now `(state, staticState) => number`; added `ChartSeries.staticVar?: string` (resolved against the static slice, plotted as a flat line). [SimCharts.tsx](src/sim/components/SimCharts.tsx) re-reads `getStatic` per tick so retunes aren't stale.
- `SceneHandler.update` / `ScenePlugin.update` gained a 4th arg `staticState`. All [ThreeCanvas.tsx](src/sim/components/ThreeCanvas.tsx) call sites pass `getStatic(simId)`. Existing plugins with shorter signatures keep working (TS allows fewer params).

Backward compatible: a model with no static blocks gets `staticState = {}` and behaves exactly as before. First (only) user: quad-l4's `params` block → `K`. Covered by [src/sim/engine/engine.test.ts](src/sim/engine/engine.test.ts) (K reaches blocks, K absent from history/getState, present in getStatic, rebuilt on reset).

**Why:** stop cloning non-time-varying consts into every history entry (memory + structuredClone cost) while keeping charts/vis able to plot/render static data. Reconciles with [[quad-on-the-fly-tuning-plan]]: "static" = const *defaults*; runtime-tunable overrides must stay in a dynamic slice merged over the static base, else tuning can't appear in history.

**Lifecycle blocks (built 2026-05-31, extends this):** `BlockConfig.lifecycle?: LifecycleConfig` adds `before`/`after`/`afterSim` hooks (each `{exportName, defaultFn}`). The quad `params` block was renamed to the `lifecycle` block ([src/sim/models/lib/quad/lifecycle.ts](src/sim/models/lib/quad/lifecycle.ts)): `beforeSim()` is the static producer (→ K, incl. new `simDuration` const); `before(state)`/`after(state)` run around the block loop; `afterSim(state)` runs once on stop. The old `validator` block was DELETED and its logic moved into `after()` (writes `state.validator` into the dynamic bus, so charts unchanged). Engine ([engine.ts](src/sim/engine/engine.ts)): hooks stored in `activeFns` under synthetic `sourceId::exportName` keys (HOOK_KEY) so staging/revert reuse existing machinery; `runLifecycle` merges static+`tick` into the hook input then strips them before persisting; `after()` returning `false` (when `tick >= K.simDuration`) stops the sim — the tick that triggered the stop is NOT committed, so exactly `simDuration` ticks land in history. `afterSim` fires on ANY running→stopped transition (natural/manual/error) via `stopSim`; unlike per-tick hooks, **afterSim's returned state IS committed to live `inst.state` and listeners are notified** (injected static keys + `tick` stripped first) — so a teardown hook can finalize a verdict. It does NOT push a new history entry (runs after the last committed tick). The quad lifecycle uses this: `after()` updates `validator.passCount`/`passTotal` live (X/N) via a `simTest(state)` helper that returns `{passed,total}` over an array of criteria (laps>=REQUIRED_LAPS, tick<=simDuration, lapErr<LAP_ERR_LIMIT, avgErr<AVG_ERR_LIMIT); `afterSim()` sets `validator.pass` = 1 if passed===total else 0. `validator.pass` is tri-state: -1 running (initialState), 1 pass, 0 fail. Old `PASS_AVG_ERR_LIMIT` const removed; thresholds REQUIRED_LAPS/LAP_ERR_LIMIT/AVG_ERR_LIMIT + simDuration(5000) added to QuadConsts. infoOverlay Pass row shows `X/N` while pass<0, then `X/N PASS|FAIL`. Multi-export source compiled via shared [engine/compile.ts](src/sim/engine/compile.ts) `compileSource(code, names)`; lifecycle default fns are compiled FROM the rendered source string (single source of truth, no TS/string drift). Covered in [engine.test.ts](src/sim/engine/engine.test.ts).

**Diagram gotcha (fixed):** [SimBlocksDiagram.ts](src/sim/components/SimBlocksDiagram.ts) `analyzeConnections` derives edges by running each block's `defaultFn(mapStateIn(initialState))`. Once `K` left `initialState` (now static), every block reading `state.K.*` threw in `getWritePaths` and the `catch{return []}` silently dropped ALL its outgoing edges — so `blocksDiagram` "always-visible" edges vanished (a config edge only renders if the dataflow analysis also found it). Fix: `analyzeConnections` rebuilds the static slice via `computeStaticSlice(config)` and analyzes against `{ ...initialState, ...slice }`, mirroring the engine. **When rolling the static slice to other models, also re-point their `blocksDiagram`:** an edge the analysis can't find is silently filtered, not drawn. For quad-l4 the lifecycle block's real edges are `lifecycle→*` (it writes K, everyone reads it); the old `world→validator`/`mission→validator` input edges became invalid when validator moved into the `after()` hook (hooks aren't inspected by the analyzer). A throwaway test confirmed all 11 quad-l4 edges resolve.
