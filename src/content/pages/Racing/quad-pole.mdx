# Quad Pole — waypoint entry plus coordinated turn around a pole

Quad Pole is the smallest racing model that still exercises both navigation stacks:

1. Waypoint navigation (`planner_wp` + `navigator_wp`) for approach and entry.
2. Coordinated-turn navigation (`planner_cturn` + `navigator_cturn`) for the orbit segment.

The same downstream flight-control chain is used throughout:

```
mission ──► planner_wp     ──► navigator_wp     ─┐
        └─► planner_cturn ──► navigator_cturn ─┤
                                                  ├──► fc_acro ──► hw ──► world
                                              (inactive stack passes through)
```

## Route definition

The route from `quad-pole/route.ts` has three NAVIGATE steps:

| Step | Type | Target | Purpose |
|------|------|--------|---------|
| 0 | WP | (4, 3, 0) | stage before entry |
| 1 | WP | (8, 3, -3) | place the drone on the cturn start point |
| 2 | CTURN | waypoints: (8,3,-3) → (12,3,0) → (8,3,3) | half-orbit around the pole |

The mission advances WP steps by distance threshold and CTURN steps by `planner_cturn.stepStatus`.

## Coordinated-turn behavior

`planner_cturn` fits a circle through the three cturn waypoints in the xz plane, computes the signed sweep direction, and generates:

1. coordinated roll and yaw-rate sticks (for the acro rate loop),
2. sampled target position and heading for `navigator_cturn`.

`navigator_cturn` tracks the sampled target with the same position-to-attitude cascade style used in waypoint navigation, then emits normalized AETR rate sticks.

## AETR and attitude

`aetr.throttle` is direct normalized thrust in [0, 1]. Roll, pitch, and yaw are normalized desired body rates. During WP segments, `navigator_wp` drives this bus; during CTURN segments, `navigator_cturn` overwrites it.
