# Quad Ladder — staged weaving route with coordinated turns

Quad Ladder models a Jacob's-Ladder-style racing element: a sequence of climbing arcs that weave between main and guide gate centers.

The current implementation uses the same dual-stack control split as other racing models:

```
mission ──► planner_wp     ──► navigator_wp     ─┐
        └─► planner_cturn ──► navigator_cturn ─┤
                                                  ├──► fc_acro ──► hw ──► world
                                              (inactive stack passes through)
```

## Route structure

The route in `quad-ladder/route.ts` is a 7-step sequence:

| Step | Type | Purpose |
|------|------|---------|
| 0 | WP | pre-ladder staging |
| 1 | CTURN | M1 → G1 arc |
| 2 | CTURN | G1 → M2 arc |
| 3 | CTURN | M2 → G2 arc |
| 4 | CTURN | G2 → M3 arc |
| 5 | WP | post-ladder staging |
| 6 | CTURN | wide return arc back to entry side |

Each cturn step contains three waypoints `[entry, mid, exit]`. The planner fits the arc in xz, while y progression follows the step endpoints.

---

## Debug mode versus coordinated mode

This model supports two execution modes for cturn steps:

1. Debug mode (`step.debug = 1`): planner sequences straight-leg targets (entry to mid, mid to exit), navigator flies line segments.
2. Coordinated mode (`step.debug = 0`): planner outputs coordinated-turn commands and sampled arc targets for navigator tracking.

The runtime toggle in `quad-ladder.config.ts` overrides route debug flags so you can switch behavior without editing route data.

## AETR and attitude

The AETR bus is shared across both navigation stacks:

1. `aetr.throttle` is normalized thrust.
2. `aetr.roll/pitch/yaw` are normalized desired body rates consumed by `fc_acro`.
