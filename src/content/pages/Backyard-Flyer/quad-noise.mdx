# Quad noise — wind disturbance and sensor noise

**Quad noise** is now the disturbance variant of [Quad L4](/Backyard-Flyer/quad-l4). It uses the same shared quad block library end to end: lifecycle, mission, planner, navigator, `fc_acro`, hardware, `world`, `wind`, and `noise` all come from the shared library. The model itself is now just shared blocks plus quad-noise-specific configuration and visualization.

```
lifecycle (beforeSim → state.K)
    │
    ▼
wind ──► world ──► noise ──► mission ──► planner_wp ──► navigator_wp ──► fc_acro ──► hw ──► world
                               ▲            ▲               ▲                ▲
                               └──────── noisy sensors ─────┴────────────────┘
```

| Block | What it adds |
|-------|-------------|
| Shared `wind` | Random horizontal gusts applied as external forces in shared `world` |
| Shared `noise` | Gaussian noise on every sensor channel; FC reads `state.sensors`, not raw state |
| Shared `mission` / `planner_wp` / `navigator_wp` / `fc_acro` / `hw` / `world` | The same quad-l4 contracts, but driven from noisy sensors and disturbed by wind |

The quad must complete the same rectangular mission as L4. The controllers never see ground truth, only `state.sensors`, and the wind block perturbs the true physics continuously. Validation and pass/fail scoring now come from the shared lifecycle hook, just like L4.

---

## Wind

The shared `wind` block lives at the top level of state as `state.wind` and runs once per tick before everything else:

```
wind { fx, fz, ticksLeft }
 └─ if ticksLeft > 0: hold current gust
 └─ if ticksLeft = 0: sample new random gust
```

Each new gust draws a uniformly random direction in the horizontal plane and a random magnitude up to `WIND_FORCE_MAX_PCT` of `WIND_MAX_N`, held for a random duration between `WIND_DURATION_MIN_TICKS` and `WIND_DURATION_MAX_TICKS`. The shared `world` block receives `windFx` and `windFz` and adds them to the aerodynamic force before integrating velocity.

Wind acts on the true physics but not on the sensor readings — the controllers don't know a gust just hit. They have to infer it from position drift and push back through feedback.

> **Knobs in shared quad constants:** `WIND_FORCE_MAX_PCT`, `WIND_MAX_N`, `WIND_DURATION_MIN_TICKS`, and `WIND_DURATION_MAX_TICKS` set gust strength and duration. Set `WIND_FORCE_MAX_PCT = 0` to fly in calm air and observe the noise effects alone.

---

## Sensor noise

The shared `noise` block runs immediately after `wind`, before any FC logic:

```
true state (pos, vel, attitude, angularVel)
    ↓  Box-Muller Gaussian
state.sensors (pos, vel, attitude, angularVel)
```

Every component of every sensor channel gets an independent zero-mean Gaussian sample added to it each tick. The standard deviations model plausible hardware:

| Channel | Std dev | Analogue |
|---------|---------|---------|
| `pos` | 0.01 m | GPS position fix |
| `vel` | 0.01 m/s | Velocity estimate (GPS doppler / INS) |
| `attitude` | 0.0001 rad (~0.006°) | IMU attitude |
| `angularVel` | 0.005 rad/s | Gyroscope |

The shared flight stack reads exclusively from `state.sensors`: mission, planner, navigator, and `fc_acro` all see noisy data. The true `pos`, `vel`, `attitude`, and `angularVel` fields are only consumed by `world` and by the lifecycle validator when it measures actual tracking error.

> **Knobs in shared `noise.ts`:** Increase `POS_STD` to simulate a degraded GPS fix (try 0.5 m). Increase `ANG_VEL_STD` to simulate a noisy gyro — the inner attitude loop is the most sensitive to this because the derivative term amplifies high-frequency jitter.

---

## Shared architecture + explicit disturbances

The point of this refactor is structural: `quad-noise` now inherits the same quad-l4 split of responsibilities, using only shared blocks.

- `lifecycle` owns constants, validation, and pass/fail scoring.
- `mission` remains a pure step/status sequencer.
- `planner_wp` owns only waypoint completion.
- `navigator_wp` converts noisy state into AETR sticks.
- `fc_acro` still receives only AETR sticks and measured angular rates.
- `wind`, `noise`, and `world` are shared blocks too; quad-noise enables the disturbance inputs while quad-l4 leaves wind at zero.

That makes the disturbance model an additive extension of L4 rather than a parallel copy of the older flight stack.
