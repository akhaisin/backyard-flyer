# Course structure

The course is a **work in progress**. The full curriculum will build up from a single counter to a full quadcopter with attitude control — but for now, four simulations are available to explore. Each one runs live in the browser; you can read, edit, and restart any block.

## Available now

- **[Inc — minimal simulation](#sim-demo/inc)** — one block, one number, one tick per second. The smallest possible model. Useful for verifying the editor + run loop before tackling anything physical.

- **[PID tutorial — control fundamentals](#sim-demo/pid-tutorial)** — a single 1D plant driven by a PID controller. Live sliders for target, gains (Kp, Ki, Kd), and plant parameters (mass, damping) let you build intuition for what each term does — start with pure P, add D to damp oscillation, add I to kill steady-state error.

- **[Floater — multi-block model with simulated hardware](#sim-demo/floater)** — a sphere chasing waypoints in 3D. Four blocks (`mission → fc → hw → world`) demonstrate how a controller, an actuator with inertia, and a physics integrator are layered. State is structured into sub-trees (`pos`, `vel`, `thrust.desired/actual`, `mission.target`).

- **[PD vs PID — two controllers, side by side](#sim-demo/floater-pid)** ⭐ *Recommended* — two floaters fly mirrored waypoint paths. One uses a PD controller (proportional + damping), the other a full PID. Same hardware, same physics — only the control law differs. Includes a note on why *pure* P can't converge (think planetary orbits).

- **[Quad L1 — full mission sequence](#Backyard-Flyer/quad-l1)** ⭐ *Recommended* — a quadcopter that executes a complete autonomous mission: arm, take off, navigate a rectangular route through four waypoints, return home, land, and disarm. The `mission` block is a seven-phase state machine; `world` includes a simple ground-contact model (per-tick horizontal friction on landing).

- **[Quad L2 — cascaded controllers: navigator + stabilizer](#Backyard-Flyer/quad-l2)** — the same mission, but the flight controller is split into two independent blocks: `fc_navigator` converts position error into desired attitude and total thrust; `fc_stabilizer` tracks that attitude and drives the motors. The interface between them — `{ roll_des, pitch_des, yaw_des, thrust }` — is live in a dedicated chart so you can watch what the navigator asks of the stabilizer during every manoeuvre.

- **[PID auto-tuning — STR](#sim-demo/pid-tune-str)** ⚠️ *Work in progress.* Self-Tuning Regulator: identify the plant online with RLS, then derive PID gains via pole placement. Demonstrates the *idea* of model-based auto-tuning; the implementation can still drift or get stuck under aggressive setpoint changes — re-tune or toggle AUTO/MANUAL to recover. The next chapter shows a more robust approach.

- **[PID auto-tuning — Relay-feedback](#sim-demo/pid-tune-relay)** — Åström–Hägglund's relay method. Press *Tune Now* and the system temporarily replaces the PID with a bang-bang relay; the resulting limit cycle gives `Ku` and `Tu`, and Ziegler-Nichols yields the gains. This is the algorithm behind the "auto-tune" button on most industrial PID controllers.

More models (attitude control, real-world disturbances, full quadcopter) will follow.
