# Quad C1b — pre-staged chase

**Quad C1b** extends the c1 chase scenario with a pre-staging leg, mirroring the w1b gate approach. Instead of immediately pursuing the target, the drone first flies to a fixed *pre-stage point* on the target's trajectory, then commits to direct pursuit from there.

---

## The scenario

Same four-sided 10 × 10 m square as c1a. The key difference: each step has a `preStageDist` (5 m), so the drone first flies to the midpoint of the target's segment before switching to pursuit.

| Step | Spawn | Destination | Pre-stage point |
|------|-------|-------------|-----------------|
| 0 | (5, 5, −5) | (5, 5, 5) | (5, 5, 0) |
| 1 | (5, 5, 5) | (−5, 5, 5) | (0, 5, 5) |
| 2 | (−5, 5, 5) | (−5, 5, −5) | (−5, 5, 0) |
| 3 | (−5, 5, −5) | (5, 5, −5) | (0, 5, −5) |

Once the drone reaches the pre-stage point it latches (`preGateDone = 1`) and switches to direct pursuit for the rest of the attempt.

---

## planner_c1b: pre-stage then pursue

```
if not staged (preGateDone == 0):
  carrot = step.pos + preStageDist * normalize(step.dest − step.pos)
  yaw    = face pre-stage point
  if dist(quad, preStage) < PREGATE_THRESHOLD → latch preGateDone = 1

if staged:
  carrot = target_c1.pos   (direct pursuit, same as c1a)
  yaw    = face target
  if dist(quad, target) < threshold  → STATUS_COMPLETED
  if target.phase == LAPPED          → STATUS_RESTART
```

The pre-stage latch resets on every non-NAVIGATE phase (restart fly-back, takeoff, RTH) so each new attempt starts with a fresh staging run.

> **Try it:** reduce `preStageDist` toward 0 to approach c1a behaviour, or increase it to position the drone further along the trajectory — potentially ahead of the target.
